## 1. Введение

Поиск максимального элемента в массиве является базовой операцией в обработке данных и встречается во многих алгоритмах. При работе с большими объёмами данных (миллионы и миллиарды элементов) последовательная обработка становится узким местом производительности. 

Целью данной работы является:
- Реализация эффективного последовательного алгоритма поиска максимума
- Разработка параллельной версии с использованием MPI
- Сравнительный анализ производительности и масштабируемости
- Оценка эффективности параллелизации на больших объёмах данных

Ожидаемый результат - линейное или близкое к линейному ускорение при увеличении количества процессов на достаточно больших данных.

## 2. Постановка задачи

**Дано:** 
- Целое число N > 0 - размер вектора

**Требуется:** 
- Найти максимальный элемент среди N целых чисел

**Формат данных:**
- Входные данные: целое число N (размер вектора)
- Значения элементов вектора генерируются детерминированно по формуле: `value[i] = (i * 7) % 2000 - 1000`
- Выходные данные: целое число - максимальный элемент вектора

**Ограничения:**
- N > 0
- Значения элементов: -1000 ≤ value[i] ≤ 999
- Диапазон индексов: 0 ≤ i < N

**Примечание:** Использование детерминированной формулы вместо генератора случайных чисел обеспечивает:
- Стабильные и воспроизводимые измерения производительности
- Отсутствие накладных расходов на генерацию данных
- Минимальное использование памяти O(1)
- Возможность точной верификации результатов

## 3. Базовый алгоритм (последовательный)

Последовательный алгоритм поиска максимума выполняет линейный проход по всем элементам вектора:

**Алгоритм:**
```
1. Инициализировать max_elem = MIN_INT
2. Для каждого индекса i от 0 до N-1:
   a. Вычислить value = (i * 7) % 2000 - 1000
   b. Если value > max_elem, то max_elem = value
3. Вернуть max_elem
```

**Псевдокод:**
```cpp
int FindMaxSequential(int N) {
    int max_elem = INT_MIN;
    
    for (int i = 0; i < N; i++) {
        int value = (i * 7) % 2000 - 1000;
        if (value > max_elem) {
            max_elem = value;
        }
    }
    
    return max_elem;
}
```

**Сложность:**
- Временная: O(N)
- Пространственная: O(1) - не требуется выделение памяти под массив

**Особенности:**
- Значения вычисляются "на лету" по детерминированной формуле
- Не требуется хранение всего массива в памяти
- Один проход по данным (single-pass algorithm)

## 4. Схема параллелизации

### 4.1 Декомпозиция данных

Используется **блочная декомпозиция** виртуального вектора между процессами:

```
Процесс 0: [0, ..., chunk_size + (0 < remainder ? 1 : 0) - 1]
Процесс 1: [start_1, ..., end_1]
...
Процесс P-1: [start_P-1, ..., N-1]
```

Размер блока для каждого процесса вычисляется с учётом остатка:
```cpp
chunk_size = N / P
remainder = N % P
start[rank] = rank * chunk_size + min(rank, remainder)
end[rank] = start[rank] + chunk_size + (rank < remainder ? 1 : 0)
```

### 4.2 Схема коммуникации

Используется **коллективная редукция** по дереву:

```
┌─────────┐
│ Master  │  1. Broadcast размера N
│ (rank 0)│ ────────────────────────► Все процессы
└─────────┘

┌─────────┐  ┌─────────┐  ┌─────────┐
│ Rank 0  │  │ Rank 1  │  │ Rank P-1│
│ Блок 0  │  │ Блок 1  │  │ Блок P-1│
└────┬────┘  └────┬────┘  └────┬────┘
     │            │            │
     ▼            ▼            ▼
  local_max    local_max    local_max
     │            │            │
     └────────────┴────────────┘
           MPI_Allreduce(MAX)
           /       |       \
          ▼        ▼        ▼
      ┌───────┐┌───────┐┌───────┐
      │Rank 0 ││Rank 1 ││Rank P-1│
      │Max=999││Max=999││Max=999 │
      └───────┘└───────┘└───────┘
```

### 4.3 Роли процессов

- **Процесс 0 (Master):**
  - Рассылает размер вектора N через `MPI_Bcast`
  - Вычисляет локальный максимум для своего блока
  - Получает глобальный максимум через `MPI_Allreduce`
  - Сохраняет результат

- **Процессы 1..P-1 (Workers):**
  - Получают размер вектора N через `MPI_Bcast`
  - Вычисляют локальный максимум для своего блока
  - Получают глобальный максимум через `MPI_Allreduce`

### 4.4 Коммуникационные операции

1. **MPI_Bcast** - рассылка размера вектора:
   - Отправитель: процесс 0
   - Получатели: все процессы
   - Данные: 1 целое число (размер вектора)
   - Сложность: O(log P)

2. **MPI_Allreduce** - сбор и рассылка максимумов:
   - Операция: MPI_MAX
   - Отправители: все процессы
   - Получатели: все процессы
   - Данные: 1 целое число (локальный максимум → глобальный максимум)
   - Сложность: O(log P)

**Общая коммуникационная сложность:** O(log P)

**Преимущества схемы:**
- Минимальные коммуникационные затраты - только размер и результат
- Отсутствие передачи самих данных (генерация локально)
- Оптимальная балансировка нагрузки
- Масштабируемость до больших P

### 5.2 Важные допущения

1. **Детерминированная генерация:** Все процессы используют одну и ту же формулу генерации значений, что гарантирует консистентность результатов
2. **Целочисленная арифметика:** Используются только целые числа типа `int`
3. **Положительный размер:** N > 0 проверяется на этапе валидации
4. **Синхронная коммуникация:** Используются блокирующие коллективные операции MPI

### 5.3 Граничные случаи

- **N = 1:** Один элемент - корректно обрабатывается
- **N < P:** Процессов больше, чем элементов - некоторые процессы получают пустые блоки
- **N % P ≠ 0:** Остаток распределяется между первыми `remainder` процессами
- **Простое N:** При простом числе элементов балансировка остаётся эффективной

### 5.4 Использование памяти

**Последовательная версия:**
- O(1) - константная память, массив не хранится

**Параллельная версия:**
- O(1) на каждом процессе
- Общая память: O(P) - только для хранения локальных максимумов в процессе редукции
- Отсутствие глобального массива данных

**Преимущество:** Алгоритм не зависит от размера доступной памяти и может работать с произвольно большими N.

### 7.2 Производительность

**Теоретические оценки:**

Для вектора размером N и P процессов:

- **Время последовательной версии:** T_seq = N × t_op, где t_op - время одной операции
- **Время параллельной версии:** T_par = N/P × t_op + T_comm
- **Время коммуникации:** T_comm = O(log P) - коллективные операции
- **Теоретическое ускорение:** Speedup = T_seq / T_par ≈ P (при N >> P и T_comm << T_comp)
- **Эффективность:** Efficiency = Speedup / P

**Ожидаемые результаты** (для N = 100,000,000):

| Режим | Процессов | Время, с | Ускорение | Эффективность |
|-------|-----------|----------|-----------|---------------|
| seq   | 1         | T        | 1.00      | N/A           |
| mpi   | 2         | ~0.50×T  | ~2.00     | ~100%         |
| mpi   | 4         | ~0.25×T  | ~4.00     | ~100%         |
| mpi   | 8         | ~0.13×T  | ~7.80     | ~97%          |

**Анализ производительности:**

1. **При малом количестве процессов (P ≤ 4):**
   - Ожидается близкое к линейному ускорение
   - Коммуникационные затраты минимальны
   - Эффективность близка к 100%

2. **При среднем количестве процессов (4 < P ≤ 16):**
   - Хорошее ускорение, немного ниже линейного
   - Коммуникация начинает сказываться
   - Эффективность 85-95%

3. **При большом количестве процессов (P > 16):**
   - Ускорение замедляется
   - Коммуникация становится заметной
   - Эффективность может снижаться до 70-80%

**Узкие места:**

1. **Коммуникационные затраты:** При очень большом P накладные расходы на MPI_Bcast и MPI_Allreduce становятся заметными
2. **Дисбаланс нагрузки:** При N % P ≠ 0, но минимизирован равномерным распределением остатка
3. **Стоимость генерации:** Вычисление формулы `(i * 7) % 2000 - 1000` добавляет постоянные накладные расходы

**Преимущества реализации:**

- Отсутствие передачи данных между процессами (кроме размера и результата)
- Коммуникационная сложность O(log P) не зависит от N
- Минимальное использование памяти O(1) на процесс
- Оптимальная балансировка нагрузки

### 7.3 Масштабируемость

**Сильная масштабируемость (Strong Scaling):**
- При фиксированном N = 100 млн и увеличении P ожидается сублинейное ускорение
- Эффективность остаётся высокой до P ≈ N/10000 (примерно 10000 процессов)

**Слабая масштабируемость (Weak Scaling):**
- При фиксированной нагрузке на процесс (N/P = const) и увеличении N и P одновременно
- Ожидается постоянное время выполнения
- Коммуникационные затраты растут как O(log P)

**Граница масштабируемости:**
- Алгоритм эффективен при N/P > 1000 (минимум 1000 элементов на процесс)
- При N/P < 100 коммуникация начинает доминировать

## Приложение

### Ключевые фрагменты кода

**Последовательная версия (SEQ):**

```cpp
bool DergachevAMaxElemVecSEQ::RunImpl() {
  if (GetInput() <= 0) {
    return false;
  }

  int size = GetInput();
  
  InType max_elem = std::numeric_limits<InType>::min();
  
  for (int i = 0; i < size; i++) {
    InType value = (i * 7) % 2000 - 1000;
    
    if (value > max_elem) {
      max_elem = value;
    }
  }
  
  GetOutput() = max_elem;
  return true;
}
```

**Параллельная версия (MPI) - основной алгоритм:**

```cpp
bool DergachevAMaxElemVecMPI::RunImpl() {
  int rank = 0;
  int size = 0;
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &size);
  
  int vec_size = 0;
  
  if (rank == 0) {
    vec_size = GetInput();
    if (vec_size <= 0) return false;
  }
  MPI_Bcast(&vec_size, 1, MPI_INT, 0, MPI_COMM_WORLD);
  
  int chunk_size = vec_size / size;
  int remainder = vec_size % size;
  int start_idx = rank * chunk_size + std::min(rank, remainder);
  int end_idx = start_idx + chunk_size + (rank < remainder ? 1 : 0);
  
  InType local_max = std::numeric_limits<InType>::min();
  
  for (int i = start_idx; i < end_idx; i++) {
    InType value = (i * 7) % 2000 - 1000;
    
    if (value > local_max) {
      local_max = value;
    }
  }
  
  InType global_max = std::numeric_limits<InType>::min();
  MPI_Allreduce(&local_max, &global_max, 1, MPI_INT, MPI_MAX, MPI_COMM_WORLD);
  
  GetOutput() = global_max;
  
  return true;
}
```

**Формула распределения данных:**

```cpp
int chunk_size = N / P;              
int remainder = N % P;               
int start = rank * chunk_size + min(rank, remainder);
int end = start + chunk_size + (rank < remainder ? 1 : 0);
```
